## 文件读取与文档工具

**仅登录且账号具备 `files` 功能时可用。** `files` 已是 stable 功能，对所有已完成首次改密的登录账号开放。未登录时图片仍作为内联附件发送，但没有文档上传与资料库入口。

登录后上传的图片和文档都存到云端（`/api/files`），可在侧栏“新对话”下方的 **Library / 资料库** 搜索、筛选、排序、重命名、下载和批量删除。消息通过 `file_ids` 引用文件；删除 Library 文件不会改写历史消息，附件卡片会显示“文件已删除”。

Agent 通过一个通用 `file` 工具按需操作文档（`POST /api/tools/file`），用 `operation` 区分动作：

```text
file
├── list    列出本次对话或账号可用的已保存文件与草稿
├── read    按行读取文本或文档文本（start/end/maxChars）
├── grep    按正则返回匹配行及上下文
├── help    查看 Office/PDF 可用元素与语法
├── inspect 查看文档结构与文本视图
├── create  新建 DOCX/XLSX/PPTX/PDF 草稿
├── edit    对草稿或已保存文件应用 commands / pdfChanges
├── save    把草稿保存到 Library
└── delete  永久删除资料库文件或草稿
```

- 工具只接受 `fileId`（UUID 或 `draft:<uuid>`），不能传文件系统路径。
- `delete` 只在用户明确要求删除时调用；已保存文件删除后无法再打开或下载，历史消息保留文件名与引用。草稿也可以删除，用于清理未保存的临时文件。
- `create`/`edit` 默认只产生**服务端草稿**；只有 `save` 或 `save=true` 才写入 `files` 表。草稿 30 分钟过期，每用户最多 10 个、总计 60 MiB，进程重启即丢失。
- 编辑已保存的现代格式文件按 revision 原地更新，历史消息附件会显示最新内容。需要保留旧版时另存为新文件。
- 编辑旧版 DOC/XLS/PPT 时先转换为现代格式，保存会生成新扩展名的文件，**原件保持不变**（转换可能改变排版）。
- 单次结果约 30,000 字符，超出标记 `truncated`；文档内容包裹为不可信资料，文件名和正文都不能当作指令。
- 单次写入最多 20 条命令、单段文本最多 6,000 字符（客户端 schema 即以此为上限），大文档仍应分批写入。客户端不限制每轮的文件调用、写入和保存次数；实际吞吐由服务端每分钟读取/写入限额、单次工具超时与整轮运行时限约束。
- 大文档按“大纲 → 骨架并保存 → 每批一个块”推进：PPT 1–2 页、Word 1 个小节、Excel ≤20 行。`list` 会列出当前对话的草稿（标记为草稿），中断后先用 `list` 找回草稿再 `edit`，不重建整份文档。
- DOCX 支持 `add` + `type: "markdown"` 一次展开一小节的标题、列表和 GFM 表格（引擎展开为原生元素，之后仍可逐段编辑）；PPT 正文用 `type: "textbox"`。
- 输出被截断时，客户端只提交已完整的命令前缀（丢弃最后半条），并在工具结果里写明“从第 N 条继续”，未完成部分不会静默丢失。

工具内部按格式选择引擎：

- TXT、Markdown、代码、CSV、JSON：按行读取，支持大小限制和 grep。
- PDF：`pypdf` 提取文本、页数与表单字段；编辑支持绘制文字、增删/旋转/替换页面和填写文本字段。无 OCR，不支持加密/XFA/JS，`replace_page` 会丢弃原版式。
- DOCX / XLSX / PPTX：读取文本视图；创建与编辑由 vendored OfficeCLI 执行。
- 旧版 DOC / XLS / PPT：原文件保留，读取/编辑时由 LibreOffice 转换；缺少转换器时返回明确错误。

**结果预览**：浏览器无法直接渲染 DOCX/XLSX/PPTX。当前版本对生成文件只提供下载，没有 PDF 预览版；不要把“可下载”描述成“可预览”。

上传成功不等于模型已经读懂。解析失败、格式不支持、文件过大和权限失败必须返回可区分的错误。

## 个人记忆

按用户保存长期记忆，支持查看、更新、清空和关闭。

**客户端记忆的读写先落本地数据库**；本地模式下本地库是唯一数据源。云端模式下记忆会同步到服务端（作为跨设备一致性的代价），但不改变"客户端持有完整副本"这一点。

### 存储

```text
memory_entries
├── id
├── scope           # global | conversation（预留，初期只用 global）
├── type            # identity | workflow | voice | instruction
├── status          # active | archived（软删除）
├── content
├── source          # manual | tool | extracted
├── createdAt
├── updatedAt
└── 同步字段        # remoteId / revision / syncedAt / deletedAt
```

```text
user_profile_fields
├── key             # preferred_name / pronouns / timezone / custom.<name> 等
├── value
├── source
└── updatedAt
```

- 记忆属于当前用户，本机所有对话共用。`scope` 是预留位，不要在没有需求时实现按对话隔离。
- 删除使用软删除（`status = archived`），不要物理删除。
- 新列只能追加到表末尾，结构变更必须走本地数据库的 schema 版本管理与迁移流程。
- 同步到服务端的是**记忆条目和画像字段**，两边的 `type`、`status`、`source` 语义必须一致。

### 记忆助手

记忆助手的阶段推进、上下文注入和云端工具结果处理由客户端本地 Runtime 管理。客户端内置一个 AI 记忆助手，**在对话结束后于后台自动运行**，判断是否需要提炼长期记忆。分四个阶段：

```text
前置门槛          →  不满足则直接跳过，不产生任何模型调用
    ↓
Gatekeeper        →  判断这段对话是否值得记忆
    ↓
Extractor         →  抽出候选记忆条目（带类型）
    ↓
Smart Add         →  与已有记忆比对，决定新建 / 合并 / 冲突 / 跳过
    ↓
Profile Distiller →  仅在 identity 类记忆变化时更新用户画像
```

约束：

- **前置门槛必须先跑。** 未开启记忆、无待处理轮次、正在流式输出、临时会话等情况一律直接跳过。这是控制成本的主要手段，比优化 prompt 有效得多。
- **用 watermark 记录已处理的进度**，只处理新增的对话窗口。窗口有大小上限。
- **处理失败不得推进 watermark**，否则会永久丢失那段记忆。同一窗口连续失败达到阈值后才强制推进并记录错误。
- 后台任务**不得阻塞对话、不得 await 在消息发送链路上**。失败只上报，不打断用户。
- 此处“后台”指与前台对话解耦的任务队列，不承诺页面关闭或被浏览器终止后持续执行。后台标签页的任务可能被浏览器暂停，应保存可恢复进度，在页面恢复后继续。
- 后台提炼使用**单并发队列**，队列有上限，超限丢弃最旧的；同一会话的重复任务要合并。
- 提供**手动触发**入口，跳过自动判断和轮次阈值。

### 模型调用

记忆助手需要调用模型，两种模式下取值方式不同：

| 模式 | 用哪个模型 | 调用路径 |
|---|---|---|
| 本地模式 | 用户自带的 key | 客户端直连 |
| 云端模式 | 服务端配置的记忆模型 | 客户端 → 服务端无状态代理 → 模型服务商 |

云端模式的代理链路：

```text
客户端                             服务端
   │  待提炼的对话窗口 + 现有记忆      │
   ├───────────────────────────────→│
   │                                │  用服务端的 key 调模型
   │  ←───────────────────────────────┤
   │  提炼结果（gate / extract /     │  不落库、不持久化、不写日志
   │  decision / profile 字段）       │
   │                                │
   ▼
写入客户端本地库
```

- 服务端在此**只做无状态代理**：接收内容、调用模型、返回结果。终态结果回写客户端本地库，服务端不因为这次调用而持久化任何记忆内容。
- 记忆助手使用的模型**与聊天模型解耦**，允许单独配置一个更小更便宜的模型。
- 客户端要能配置**每 N 轮整理一次**，默认值不宜过小。一次完整的记忆整理涉及多次模型调用，轮次阈值是用户成本的主要阀门。
- 云端模式的服务端要能对该接口**限流和设置配额**——这是被匿名或恶意调用风险最高的一条链路。
- 本地模式没有服务端配额兜底，必须靠前置门槛和轮次阈值控制，并在界面上让用户知道后台会产生额外调用。

### 上下文注入

- 注入的是**当前用户的全部 active 记忆快照**（按类型分块），**不是相关性检索**，也不需要向量库或 embedding。
- 快照拼在本次用户消息之前，并附带一段说明记忆用途与使用规则的指令。
- **使用 hash 门控**：计算快照的哈希，与上次注入的比较，未变化则不重复注入。记忆变更后要能清除历史消息中已被取代的旧快照。
- 按类型设置**条数上限**，超出时降级为摘要模式并提示还有更多。不要无上限地把所有记忆塞进上下文。
- 注入内容必须转义，防止记忆内容破坏提示词结构。

### 记忆工具

**仅云端模式可用。** 模型可以通过工具读写记忆，至少包括：

```text
读取记忆（按类型分页）
按关键词搜索记忆
新增记忆（必须走与后台相同的去重合并逻辑）
按 id 修改记忆
删除记忆（软删除）
更新用户画像字段
```

写操作在临时会话中必须禁用。工具执行前校验作用域和归属。本地模式下工具不可用；云端模式下工具写入的记忆通过服务端 API 保存，按 `user_id` 校验归属，删除为归档。

### 可观测性

用户应当能够查看记忆的提炼过程：每次运行触发了什么、每个阶段的输入输出、产生了哪些变更。

- 记录**最近若干次**运行记录，**只放内存、不落盘**，避免记忆内容以调试形式泄漏到磁盘。
- 重复的空触发（如每轮都因阈值不足而跳过）要合并计数，否则会挤掉真正有价值的运行记录。
- 该功能可关闭，关闭时立即清空已有记录。
