# 文件读取与个人记忆

[文档索引](README.md)

## 文件读取

**仅云端模式可用。** 本地模式不提供文件读取，也不显示资料库和上传入口。

非文本文件不要把原始二进制直接塞进模型上下文，应由服务端的文件工具按需读取：

```text
file_tools
├── list：列出本次对话可用的附件
├── read：读取文本或指定行范围
└── grep：按关键词或正则返回匹配行及上下文
```

工具内部按格式选择解析器：

- TXT、Markdown、代码、CSV、JSON：按行读取，支持大小限制和 grep。
- PDF：提取页面文本；扫描件需要 OCR，不能假设所有 PDF 都有文本层。
- DOCX / XLSX / PPTX：只读文本视图，保留工作表和单元格地址一类的定位信息。
- 旧版 DOC / XLS / PPT：必要时转换后读取，原件保留，只把最终结果入库。

工具每次只返回必要的片段并限制单次结果大小，避免把整本 PDF 或整个工作簿一次性放进上下文。

**结果预览**：文档类交付物要额外提供 PDF 预览版。客户端在移动端无法原生渲染 DOCX/XLSX/PPTX，只给下载会形成死路。

上传成功不等于模型已经读懂。解析失败、格式不支持、文件过大和权限失败必须返回可区分的错误。

## 个人记忆

按用户保存长期记忆，支持查看、更新、清空和关闭。

**客户端记忆的读写先落本地数据库**；本地模式下本地库是唯一数据源。云端模式下记忆会同步到服务端（作为跨设备一致性的代价），但不改变"客户端持有完整副本"这一点。

### 存储

```text
memory_entries
├── id
├── scope           # global | conversation（预留，初期只用 global）
├── type            # identity | workflow | voice | instruction
├── status          # active | archived（软删除）
├── content
├── source          # manual | tool | extracted
├── createdAt
├── updatedAt
└── 同步字段        # remoteId / revision / syncedAt / deletedAt
```

```text
user_profile_fields
├── key             # preferred_name / pronouns / timezone / custom.<name> 等
├── value
├── source
└── updatedAt
```

- 记忆属于当前用户，本机所有对话共用。`scope` 是预留位，不要在没有需求时实现按对话隔离。
- 删除使用软删除（`status = archived`），不要物理删除。
- 新列只能追加到表末尾，结构变更必须走本地数据库的 schema 版本管理与迁移流程。
- 同步到服务端的是**记忆条目和画像字段**，两边的 `type`、`status`、`source` 语义必须一致。

### 记忆助手

记忆助手的阶段推进、上下文注入和云端工具结果处理由客户端本地 Runtime 管理。客户端内置一个 AI 记忆助手，**在对话结束后于后台自动运行**，判断是否需要提炼长期记忆。分四个阶段：

```text
前置门槛          →  不满足则直接跳过，不产生任何模型调用
    ↓
Gatekeeper        →  判断这段对话是否值得记忆
    ↓
Extractor         →  抽出候选记忆条目（带类型）
    ↓
Smart Add         →  与已有记忆比对，决定新建 / 合并 / 冲突 / 跳过
    ↓
Profile Distiller →  仅在 identity 类记忆变化时更新用户画像
```

约束：

- **前置门槛必须先跑。** 未开启记忆、无待处理轮次、正在流式输出、临时会话等情况一律直接跳过。这是控制成本的主要手段，比优化 prompt 有效得多。
- **用 watermark 记录已处理的进度**，只处理新增的对话窗口。窗口有大小上限。
- **处理失败不得推进 watermark**，否则会永久丢失那段记忆。同一窗口连续失败达到阈值后才强制推进并记录错误。
- 后台任务**不得阻塞对话、不得 await 在消息发送链路上**。失败只上报，不打断用户。
- 此处“后台”指与前台对话解耦的任务队列，不承诺应用进入系统后台或被终止后持续执行。移动端任务可能被挂起，应保存可恢复进度，在应用恢复后继续。
- 后台提炼使用**单并发队列**，队列有上限，超限丢弃最旧的；同一会话的重复任务要合并。
- 提供**手动触发**入口，跳过自动判断和轮次阈值。

### 模型调用

记忆助手需要调用模型，两种模式下取值方式不同：

| 模式 | 用哪个模型 | 调用路径 |
|---|---|---|
| 本地模式 | 用户自带的 key | 客户端直连 |
| 云端模式 | 服务端配置的记忆模型 | 客户端 → 服务端无状态代理 → 模型服务商 |

云端模式的代理链路：

```text
客户端                             服务端
   │  待提炼的对话窗口 + 现有记忆      │
   ├───────────────────────────────→│
   │                                │  用服务端的 key 调模型
   │  ←───────────────────────────────┤
   │  提炼结果（gate / extract /     │  不落库、不持久化、不写日志
   │  decision / profile 字段）       │
   │                                │
   ▼
写入客户端本地库
```

- 服务端在此**只做无状态代理**：接收内容、调用模型、返回结果。终态结果回写客户端本地库，服务端不因为这次调用而持久化任何记忆内容。
- 记忆助手使用的模型**与聊天模型解耦**，允许单独配置一个更小更便宜的模型。
- 客户端要能配置**每 N 轮整理一次**，默认值不宜过小。一次完整的记忆整理涉及多次模型调用，轮次阈值是用户成本的主要阀门。
- 云端模式的服务端要能对该接口**限流和设置配额**——这是被匿名或恶意调用风险最高的一条链路。
- 本地模式没有服务端配额兜底，必须靠前置门槛和轮次阈值控制，并在界面上让用户知道后台会产生额外调用。

### 上下文注入

- 注入的是**当前用户的全部 active 记忆快照**（按类型分块），**不是相关性检索**，也不需要向量库或 embedding。
- 快照拼在本次用户消息之前，并附带一段说明记忆用途与使用规则的指令。
- **使用 hash 门控**：计算快照的哈希，与上次注入的比较，未变化则不重复注入。记忆变更后要能清除历史消息中已被取代的旧快照。
- 按类型设置**条数上限**，超出时降级为摘要模式并提示还有更多。不要无上限地把所有记忆塞进上下文。
- 注入内容必须转义，防止记忆内容破坏提示词结构。

### 记忆工具

**仅云端模式可用。** 模型可以通过工具读写记忆，至少包括：

```text
读取记忆（按类型分页）
按关键词搜索记忆
新增记忆（必须走与后台相同的去重合并逻辑）
按 id 修改记忆
删除记忆（软删除）
更新用户画像字段
```

写操作在临时会话中必须禁用。工具执行前校验作用域和归属。工具写入的记忆同样要落到本地库并进入同步队列。

### 可观测性

用户应当能够查看记忆的提炼过程：每次运行触发了什么、每个阶段的输入输出、产生了哪些变更。

- 记录**最近若干次**运行记录，**只放内存、不落盘**，避免记忆内容以调试形式泄漏到磁盘。
- 重复的空触发（如每轮都因阈值不足而跳过）要合并计数，否则会挤掉真正有价值的运行记录。
- 该功能可关闭，关闭时立即清空已有记录。
