# Agent Runtime、模型与工具

[文档索引](README.md)

## Agent Runtime

**Agent Runtime 统一在客户端本地运行，本地模式与云端模式共用同一套 Runtime。** 云端模式表示接入云端能力，不改变 Runtime 的运行位置。

| 职责 | 客户端本地 | 云端服务 |
| --- | --- | --- |
| Agent Loop、上下文组装、记忆注入 | 负责 | 不运行对话循环 |
| 流式事件消费、状态、取消与轮次推进 | 负责 | 响应请求并返回结果 |
| 工具选择、参数组装、结果回填与继续调用模型 | 负责 | 执行单次工具请求 |
| 网络搜索、网页读取、文件处理 | 经工具适配层调用云端 API | 校验权限并执行 |
| 模型请求 | 本地模式直连；云端模式经过模型代理 | 保管云端 key，代理单次模型请求 |

客户端 Runtime 负责：

```text
组装上下文与可用工具定义
    ↓
调用模型并消费流式事件
    ↓
如有工具调用，向云端工具 API 提交请求
    ↓
接收工具结果并回填上下文
    ↓
继续调用模型，直到完成、取消或达到限制
```

未登录时不注册云端工具，Runtime 只运行纯对话与记忆注入。登录后通过统一能力集开放工具，沿用同一套循环。

共享核心集中在客户端 `src/core/agent/`，不依赖 React、DOM、Expo 页面、聊天状态或设置模块。Web 与移动端通过同一接口提交请求、订阅运行状态和接收回复：

```text
src/core/agent/
├── runtime.ts         # createAgentRuntime：校验、运行状态、批量回复、取消与资源释放
├── runner.ts          # pi-agent 创建、流式事件、超时与错误处理
├── context.ts         # 引用、图片、历史上下文与请求长度检查
├── types.ts           # Message、MessageImage、AgentProfile 与运行状态契约
├── system-prompt.ts   # 基础系统提示与用户偏好组装
├── title.ts           # 独立的一次性会话标题请求与规范化
└── thinking-effort.ts # 跨端思考强度契约
```

- 模型传输与协议解码放在 `src/core/llm/`，Runtime 不与某一种模型协议耦合。
- `createAgentRuntime({ onReply })` 返回 `start(request)`、`stop(conversationId?)`、`getSnapshot()`、`subscribe(listener)`、`clearError()` 和 `dispose()`；每个工作区独立创建实例。运行状态按会话记录（`runs: Record<conversationId, RuntimeRun>`）：同一会话只允许一个活动请求，不同会话可以并发；`stop(id)` 只取消指定会话，无参调用取消全部（仅用于工作区卸载）。`start` 接收模型配置、临时凭据、消息、会话/回复 ID、系统提示与思考强度；请求开始时复制输入，后续 UI 修改不改变正在运行的请求。凭据不进入可订阅状态或消息存储。运行失败写入对应助手消息（`status: 'error'`）而不是工作区级 `error`，避免后台失败串到当前打开的会话；`error` 仅承载发送前的配置/凭据/上下文校验错误。
- Runtime 默认延迟加载 `runner.ts`，也可通过 `loadRunner` 注入兼容实现。`core/llm/direct-stream.ts` 负责三种协议的流式传输；平台差异留在传输、凭据和存储适配层，不引入核心依赖。
- `features/chat/chat-runtime.tsx` 是 React 聊天适配层，只读取当前模型/凭据与偏好、处理发送/重试、把核心回复写入会话状态；通过 `useSyncExternalStore` 订阅核心状态。删除运行中的对话只取消该会话的请求，卸载工作区取消全部；切换设置或其他会话不改变生成所属会话。后台回复完成且用户不在该会话（或处于设置等全页路由）时，会话写入 `completedReadAt: null` 并在适配层生成最多 3 条临时通知卡片；打开会话后清除未读。复制文本、选区和导航继续属于聊天 UI。
- 会话标题由 `core/agent/title.ts` 通过默认 `directStream` 单独请求生成，不经过 `createAgentRuntime`：不创建运行记录、不占用会话运行槽、不被正在生成的回复阻塞，也不会写入会话历史或触发后台通知。首条消息发送后与回复并行发起，只读取首条用户消息（含引用，正文 4000、引用 2000 字符上限）；请求默认 20 秒超时并可随会话删除或工作区卸载取消。标题请求单独使用 low 思考强度并预留最多 512 输出 token，不改聊天模型的思考选择。输出经 `normalizeConversationTitle` 取首行、去掉 Markdown/“标题：”前缀与成对引号；中文等 CJK 标题最多 16 个字形，英文最多 6 词、32 字形，尽量不切断单词。备用标题使用相同限制。失败、超时、缺 key 或空输出静默返回 `null`，保留备用标题；后续回复成功后由聊天适配层重试。生成结果只替换带 `titleSource: 'auto'` 且标题仍等于请求时快照的会话，手动重命名与分支永不被覆盖。

- 按 OpenStudio 的 `prompt.ts` 组织方式，在 `buildSystemPrompt` 构建「基础指令 → current_context → 用户自定义指令 → 用户资料」时一次性加入当前本地日期、时间、UTC 偏移和 IANA 时区。一次回复创建 Agent 时固定这份 system prompt，后续搜索、读取及模型续轮直接复用，不在 stream transport 中更新时间或追加重复上下文。标题请求独立构建一次自身提示词。数据来自运行设备的时钟与 Intl 时区，不写进历史消息；联网提示不再另行提供 UTC 日期，避免跨午夜时两个日期相互矛盾。这份时间上下文不替代对实时事实的检索核实。
- 共享核心已通过无 UI 的 Node 测试，覆盖取消、加载期间停止、输入快照、销毁与订阅清理；现有 Web 调用已接入。移动端页面、凭据/数据库及实际流式传输环境仍待接入和真机验证，抽取核心不代表已完成原生端适配。
- 引用回复通过用户消息的可选 `quote` 字段进入上下文；请求组装时把引用原文作为参考资料与本次提问分开，三种模型协议共用同一格式，长度计入上下文检查。重新生成继续携带原引用；不把引用改写为系统消息，也不重发历史思考正文。
- 助手消息的可选 `feedback: 'good' | 'bad'` 由 `context.ts` 在对应助手回复之后组装为用户反馈消息，再交给 pi-agent。三种协议都携带，反馈文本计入输入长度，不改写助手原文、不推断评分原因。评分变更用于下一次请求，不更改正在生成的请求快照；取消评分后不再组装该反馈。重新生成已评分的旧版本时，用旧回复、评分及临时重答请求作为上下文；临时请求不写入历史，新版回复不继承旧评分。
- 生成中的补充或纠正走 `createAgentRuntime().steer(conversationId, message)`，返回 `'steered' | 'deferred' | false`。在思考或工具阶段发送时，活动 run 调用 pi-agent 的 `agent.steer()`，由它在当前 assistant turn 及其工具调用结束后注入，不新开 run；注入内容在模型上下文中包装为 `<user_steering_message>`，持久化正文保持用户原文，并带 `steering: true`，加载时据此还原到对应回复之前。runner 在主循环结束后继续排空 `hasQueuedMessages()`，避免消息恰好落在循环退出时被丢弃。
- 一旦最终正文已开始流式输出，`steer()` 返回 `'deferred'` 而不注入当前 run。聊天适配层先把消息暂存在内存中（不写入会话），UI 将其显示在上一条用户消息下方、流式回复之前；当前 run 结束后再以普通用户消息追加到该回复之后，并自动开启新一轮生成独立回复。阶段标记是 run 级的：`message_start` 不重置它，工具调用前的过渡文字在 `toolcall_start` 时清除，因此工具阶段仍可插队。deferred 消息不带 `steering` 标记，本地与云端最终顺序都是 `[assistant, deferred-user]`；未结束时刷新页面会丢失这些仅存在于内存的消息，符合“运行不自动恢复”的约定。该 run 已结束或不存在时 `steer()` 返回 `false`，调用方回退到普通发送。
- 当前已接入全局个性化偏好：`core/agent/system-prompt.ts` 将自定义指令和用户主动填写的资料加入基础系统提示。每次发送或重新生成时读取最新偏好并固定本次请求快照，包含系统提示长度的上下文检查在发送前执行；空偏好保持原基础提示。三种模型协议由 pi 适配发送系统提示，既有消息不被改写。此功能不执行记忆提取、记忆检索或工具调用。
- 运行状态由本地管理；需要恢复的最小进度通过本地仓储保存。临时流式事件与记忆调试记录不因此全量落盘。
- 限制最大轮次、工具调用次数和等待时间；取消时停止后续模型轮次，并尽可能取消正在执行的请求。取消不代表云端工具已经回滚。
- 客户端挂起或退出后，不承诺云端自动继续 Agent Loop；恢复策略由客户端处理。
- 服务端模型代理只处理单次模型请求，工具 API 只执行单次工具任务。服务端不组装对话循环、不自行回填工具结果或继续调用模型。

## 模型

模型与服务商配置有两种来源，按模式区分：

### 云端模式

配置留在服务端，保持一致集中的配置项：

```text
baseURL
API key
protocol
model ID
provider configuration
```

支持协议：

```text
OpenAI Chat Completions
OpenAI Responses
Anthropic Messages
```

**永远不要把服务端模型的 API key 暴露给客户端。** 客户端获取安全的服务商/模型元数据和输入能力，由本地 Runtime 发起单次模型代理请求。代理转发模型的流式响应，包括工具调用事件；后续工具调度与模型轮次由客户端推进。

### 本地模式

用户先配置服务商（名称、协议、base URL、key），再把多个模型挂到对应服务商下。支持从服务商的 `/v1/models` 目录获取模型，也允许手动添加模型 ID。

- Web key 单独保存在浏览器 IndexedDB 的 `model-credentials` 记录中，刷新后仍可用；该记录不加密，界面上必须说明。它**不写入 `model-preferences` 或工作区记录、不写入日志、不写入崩溃上报、不同步到云端**。
- 允许自定义 base URL，以覆盖兼容层服务商。
- 服务商和模型元数据按 Provider 结构保存在本地；读取旧版扁平模型配置时按协议和 Base URL 迁移分组。
- 界面要能展示当前用的是哪种模式的模型，避免用户混淆。

### 共同约束

模型的输入能力要分别记录 `text` 和 `image`，不要合并成一个笼统的多模态标志。

## 工具

**云端工具仅在已登录且具备对应能力时开放，实际执行在服务端，调度在客户端本地 Runtime。**

工具是独立模块，每个工具包含：

```text
name
description
input schema
execute()
```

执行前必须校验输入。

```text
<server-tools-module>/
├── web-tools/
├── file-tools/
└── memory/
```

工具在服务端执行前必须校验用户身份、资源归属、输入大小和运行时限制。

客户端工具适配层只负责提交调用和接收结果，不在设备上执行网络搜索、网页抓取或文件解析。本地模式不注册云端工具。

网络工具（`web_search` / `web_fetch`）仅在已登录、已完成首次改密且账号页的「启用网络工具」开关打开时注册；该开关默认开启，按用户保存在本地。开关关闭或偏好尚未加载完成时不下发工具定义，模型不会发起工具调用。每次回复创建独立的工具实例和预算：最多 6 次搜索、4 次读取调用、合计 8 个网页，读取单次最多并发 4 个页面。已知多个相关 URL 时优先通过 `urls` 批量读取；适配器用 `Promise.allSettled` 并发发起请求，不等待前页完成。部分失败保留成功页面，取消信号传给整批请求，结果按输入顺序组装。模型工具调用按 OpenStudio 的 sequential 模式逐批执行，每批内部四页并发，避免两批同时发出八个请求触发账号四请求上限。单页最多返回 50,000 字符，多页每页最多 16,000 字符并明确标记截断，避免挤爆后续模型上下文。工具结果会附带剩余预算，提醒模型不要重复搜索或伪造 URL。

读取工具的短暂网络故障、502/503/504，以及带不超过 5 秒 Retry-After 的 429，内部最多重试一次；鉴权失败、无效地址、长时间限流和主动取消不重试。认证请求保留 AbortError 和 Retry-After，不把用户取消改写成网络失败。这个自动恢复不额外占用一次模型工具调用预算。

## 联网搜索

联网搜索由 API 进程内的 `app/tools/search.py` 完成：优先 `ddgs` 的 DuckDuckGo 后端，失败、超时、限流或没有有效结果时才在剩余预算内回退 Bing RSS，规范化、去重、按关键词相关性排序后返回，**仅云端模式可用**。整次搜索默认 8 秒，DuckDuckGo 单次默认 4 秒；Bing 复用长连接并重试瞬时传输错误，连续失败会短暂熔断，避免每次都耗满预算。偏题结果向模型附带警示，不能作为已核实证据。网页读取由 `app/tools/web_fetch.py` 完成：逐跳校验重定向目标、限制下载字节数，整次默认 45 秒截止时间覆盖排队、重定向、响应体与提取，并对超时、传输错误、5xx 和短时 429 做有限重试。优先接受 Markdown/纯文本，JSON、XML、代码和 Markdown 保留原始结构；HTML 先由 trafilatura 提取 Markdown（precision 为空时改用 recall），再降级到 `html_markdown.py`（保留标题、链接、代码块和表格），最后是 lxml 纯文本。缺失或 `application/octet-stream` 的响应会嗅探前 4 KiB，二进制内容直接拒绝。404/410、拒绝访问、限流、超时和网络错误使用不同错误码；验证页和纯 JavaScript 空壳明确报错，不作为已读取证据。目前没有浏览器渲染或登录页面能力。批量读取仅将成功页面列为来源，部分失败和正文截断均明确反馈。

实现参考：[OpenCode webfetch](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/tool/plugin/webfetch.ts) 的内容协商与覆盖响应体的超时，[OpenSERP extract](https://github.com/karust/openserp/blob/main/core/server_extract.go) 和[资源配置](https://github.com/karust/openserp/blob/main/extract/config.go)的正文/完整页边界及并发预算。也查看了 [Codex web search 调用测试](https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/suite/v2/web_search.rs)，其网页处理由 web 服务端承担；当前实现不依赖该服务。

把它放在专门的工具模块之后，不要把上游地址和解析逻辑散落到代码各处；单一来源失败时降级，全部失败返回 502。

并发与成本控制集中在服务端：

- 全局 provider 信号量（搜索、抓取各 4）限制同时访问上游的总量。
- 每个账号对每种工具另有 4 个在途请求上限，超出立即返回 429，避免单个 Agent 循环占满共享容量。
- 相同查询/URL 使用 single-flight 合并并发请求，并保留短期缓存（搜索 5 分钟、网页 10 分钟），缓存失效时不会形成击穿。
- HTML 解析与正文提取移出事件循环（或置于抓取信号量内），避免单 worker 被 CPU 工作阻塞。

模型根据页面内容作出的结论必须引用真实读取过的 URL；snippet 只用于挑选来源，网页内容一律视为不可信数据，其中出现的指令不得执行。

思考区按 OpenStudio `response-process` 的结构与样式移植，标题统一为「思考过程」，不显示「生成中」「正在回复」。无底色整行标题按钮在等待阶段也可展开，尚无内容时展开区留空；折叠时不解析 Markdown。等待入口与消息正文用同一 replyId 保留展开状态，首段内容到达、正文开始、结束及下一轮回复不自动收起。详情使用 13px 灰色正文、小节点及步骤间连线，严格按 `Message.process` 事件顺序流式追加，例如「思考 → 搜索 → fetch → 再思考」，不把不同轮的思考拼到顶部或跨思考段合并工具。搜索与读取各自可折叠，运行时默认展开、结束后收起，后续手动选择保持不变。整个回复完成前标题保持运行状态，`thinkingMs` 持续计时至正文生成结束；失败/停止使用各自图标，只有成功生成最终回答才显示勾选。只返回思考、没有最终回答正文的模型响应按错误处理并保留过程。回答下方不提供来源入口，来源聚合留待后续实现。过程记录只保存在本地工作区，不进入服务端消息同步；主动取消与刷新恢复的在途步骤标为 stopped，不冒充工具失败。旧消息缺少事件顺序时仅按原有数据展示，不伪造历史阶段。

本地模式下联网搜索入口**不显示**，见「功能可见性」。不要做成灰置或点击报错。

## 当前 Web 实现

- 参考 `../openstudio/src/server/agent/models.ts` 的配置字段与三协议映射，使用固定版本 `@mariozechner/pi-agent-core` / `pi-ai` 0.73.1；服务商密钥和配置不从 OpenStudio 导入。当前仅本地文本对话，不提供工具、图片上传或云端代理。
- `core/agent/runner.ts` 创建真实 pi Agent；`core/llm/model-config.ts` 映射模型元数据；`features/chat/chat-runtime.tsx` 连接当前工作区、上下文、生命周期与消息状态。Thinking Effort 支持 Default、Low、Medium、High，由 pi-agent-core 映射到模型请求；每个会话独立保存设置，新会话沿用最近选择，旧会话读取时默认为 Default，重试沿用会话设置。一个工作区同时生成一条回复，切换聊天或进入设置不卸载 Runtime，删除正在生成的会话会取消，不重建已删会话。
- `features/models/model-settings-screen.web.tsx` 管理 Provider 与其模型；模型目录由 `core/llm/provider-catalog.web.ts` 从服务商直接获取。API key 按 Provider ID 单独存储，持久化的模型配置只保存字段白名单。
- 输入校验通过后才提交消息并清空草稿；未配置模型或缺 key 时保留草稿。流式界面约 50ms 合并一次更新；存储约 300ms 写入最新正文，结束时立即提交最终状态。停止和错误保留收到的文本；刷新时将 streaming 状态恢复为 stopped，不自动继续付费请求。
- 上下文包含当前会话已有文本，不混入其他会话或隐藏思考；使用保守字符预算检查并预留输出窗口，超限提示新建对话。默认空闲超时 120 秒，思考/正文增量和工具开始/结束均重置计时；独立总时限为 15 分钟。持续有输出的长回复不会因为达到两分钟被切断。本地模式不执行模型返回的工具调用。
- Web 密钥按工作区独立存放，与模型元数据分表，不写日志或同步；模型请求走同源中继，原生直连。错误归一为安全、可操作的提示，不持久化 SDK 原始响应。末条失败回复下将错误和重试放在同一个紧凑提示容器内；点击后立即进入 streaming，不重复提交用户问题。发送新消息或已有回复运行时，旧回复的重试按钮隐藏，历史错误说明保留。主动停止为中性提示，不提供该错误重试按钮。后续消息保留原问题和半截回复；模型上下文把半截回复明确标为未完成，仅排除空错误占位和错误元数据。手动刷新恢复 streaming 为 stopped，并停止在途工具指示，不自动重新请求模型。同步的迟到快照不能覆盖正在生成或已更新的本地消息。
- `core/platform/run-protection.web.ts` 在运行期间保护离开/刷新操作，并暂停 SDK 57 的开发 HMR；所有会话都空闲后等待 1.5 秒，让最终状态提交再恢复热更新。`dev-refresh-client.web.js` 隔离 Expo 私有开发 API 与其原生类型依赖，升级 SDK 时需验证。真实整页刷新仍会销毁客户端 Runtime，不能假装请求继续运行。
- 旧 pi 的聚合入口含 Metro 不支持的动态 Node 导入。`metro.config.js` 在 Web 中把 pi-ai 聚合入口映射为 `pi-agent-bridge.ts` 的官方事件/校验工具导出，并把 Node 环境密钥发现映射为 `pi-browser-credentials.ts`；请求由显式 streamFn 只加载三种协议，未改写依赖文件。升级 pi 时需同时检查这些固定版本的内部工具路径。

- Runtime 的 `ReplyUpdate.reasoningActive` 仍跟随 pi 的 `thinking_start/delta/end` 更新，作为内部阶段标记；整个过程头部则依据消息 streaming/complete/stopped/error 显示整轮状态，不能把 thinking_end 当成回复完成。`ReplyUpdate.process` 按事件顺序保存每段思考与工具调用，计时包含等待、所有模型子轮次、工具和答案生成；只有整轮结束才冻结。工具进度事件也会重置空闲超时。
