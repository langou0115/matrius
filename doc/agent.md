# Agent Runtime、模型与工具

[文档索引](README.md)

## Agent Runtime

**Agent Runtime 统一在客户端本地运行，本地模式与云端模式共用同一套 Runtime。** 云端模式表示接入云端能力，不改变 Runtime 的运行位置。

| 职责 | 客户端本地 | 云端服务 |
| --- | --- | --- |
| Agent Loop、上下文组装、记忆注入 | 负责 | 不运行对话循环 |
| 流式事件消费、状态、取消与轮次推进 | 负责 | 响应请求并返回结果 |
| 工具选择、参数组装、结果回填与继续调用模型 | 负责 | 执行单次工具请求 |
| 网络搜索、网页读取、文件处理 | 经工具适配层调用云端 API | 校验权限并执行 |
| 模型请求 | 本地模式直连；云端模式经过模型代理 | 保管云端 key，代理单次模型请求 |

客户端 Runtime 负责：

```text
组装上下文与可用工具定义
    ↓
调用模型并消费流式事件
    ↓
如有工具调用，向云端工具 API 提交请求
    ↓
接收工具结果并回填上下文
    ↓
继续调用模型，直到完成、取消或达到限制
```

未登录时不注册云端工具，Runtime 只运行纯对话与记忆注入。登录后通过统一能力集开放工具，沿用同一套循环。

共享核心集中在客户端 `src/core/agent/`，不依赖 React、DOM、Expo 页面、聊天状态或设置模块。Web 与移动端通过同一接口提交请求、订阅运行状态和接收回复：

```text
src/core/agent/
├── runtime.ts         # createAgentRuntime：校验、运行状态、批量回复、取消与资源释放
├── runner.ts          # pi-agent 创建、流式事件、超时与错误处理
├── context.ts         # 引用、图片、历史上下文与请求长度检查
├── types.ts           # Message、MessageImage、AgentProfile 与运行状态契约
├── system-prompt.ts   # 基础系统提示与用户偏好组装
├── title.ts           # 独立的一次性会话标题请求与规范化
└── thinking-effort.ts # 跨端思考强度契约
```

- 模型传输与协议解码放在 `src/core/llm/`，Runtime 不与某一种模型协议耦合。
- `createAgentRuntime({ onReply })` 返回 `start(request)`、`stop(conversationId?)`、`getSnapshot()`、`subscribe(listener)`、`clearError()` 和 `dispose()`；每个工作区独立创建实例。运行状态按会话记录（`runs: Record<conversationId, RuntimeRun>`）：同一会话只允许一个活动请求，不同会话可以并发；`stop(id)` 只取消指定会话，无参调用取消全部（仅用于工作区卸载）。`start` 接收模型配置、临时凭据、消息、会话/回复 ID、系统提示与思考强度；请求开始时复制输入，后续 UI 修改不改变正在运行的请求。凭据不进入可订阅状态或消息存储。运行失败写入对应助手消息（`status: 'error'`）而不是工作区级 `error`，避免后台失败串到当前打开的会话；`error` 仅承载发送前的配置/凭据/上下文校验错误。
- Runtime 默认延迟加载 `runner.ts`，也可通过 `loadRunner` 注入兼容实现。`core/llm/direct-stream.ts` 负责三种协议的流式传输；平台差异留在传输、凭据和存储适配层，不引入核心依赖。
- `features/chat/chat-runtime.tsx` 是 React 聊天适配层，只读取当前模型/凭据与偏好、处理发送/重试、把核心回复写入会话状态；通过 `useSyncExternalStore` 订阅核心状态。删除运行中的对话只取消该会话的请求，卸载工作区取消全部；切换设置或其他会话不改变生成所属会话。后台回复完成且用户不在该会话（或处于设置等全页路由）时，会话写入 `completedReadAt: null` 并在适配层生成最多 3 条临时通知卡片；打开会话后清除未读。复制文本、选区和导航继续属于聊天 UI。
- 会话标题由 `core/agent/title.ts` 通过默认 `directStream` 单独请求生成，不经过 `createAgentRuntime`：不创建运行记录、不占用会话运行槽、不被正在生成的回复阻塞，也不会写入会话历史或触发后台通知。首条消息发送后与回复并行发起，只读取首条用户消息（含引用，正文 4000、引用 2000 字符上限）；请求默认 20 秒超时并可随会话删除或工作区卸载取消。模型输出经 `normalizeConversationTitle` 取首行、去掉 Markdown/“标题：”前缀与成对引号并截断到 32 个字形。失败、超时、缺 key 或空输出静默返回 `null`，保留首条消息的截断标题；后续回复成功后由聊天适配层重试。生成结果只替换带 `titleSource: 'auto'` 且标题仍等于请求时快照的会话，手动重命名与分支永不被覆盖。
- 共享核心已通过无 UI 的 Node 测试，覆盖取消、加载期间停止、输入快照、销毁与订阅清理；现有 Web 调用已接入。移动端页面、凭据/数据库及实际流式传输环境仍待接入和真机验证，抽取核心不代表已完成原生端适配。
- 引用回复通过用户消息的可选 `quote` 字段进入上下文；请求组装时把引用原文作为参考资料与本次提问分开，三种模型协议共用同一格式，长度计入上下文检查。重新生成继续携带原引用；不把引用改写为系统消息，也不重发历史思考正文。
- 助手消息的可选 `feedback: 'good' | 'bad'` 由 `context.ts` 在对应助手回复之后组装为用户反馈消息，再交给 pi-agent。三种协议都携带，反馈文本计入输入长度，不改写助手原文、不推断评分原因。评分变更用于下一次请求，不更改正在生成的请求快照；取消评分后不再组装该反馈。重新生成已评分的旧版本时，用旧回复、评分及临时重答请求作为上下文；临时请求不写入历史，新版回复不继承旧评分。
- 当前已接入全局个性化偏好：`core/agent/system-prompt.ts` 将自定义指令和用户主动填写的资料加入基础系统提示。每次发送或重新生成时读取最新偏好并固定本次请求快照，包含系统提示长度的上下文检查在发送前执行；空偏好保持原基础提示。三种模型协议由 pi 适配发送系统提示，既有消息不被改写。此功能不执行记忆提取、记忆检索或工具调用。
- 运行状态由本地管理；需要恢复的最小进度通过本地仓储保存。临时流式事件与记忆调试记录不因此全量落盘。
- 限制最大轮次、工具调用次数和等待时间；取消时停止后续模型轮次，并尽可能取消正在执行的请求。取消不代表云端工具已经回滚。
- 客户端挂起或退出后，不承诺云端自动继续 Agent Loop；恢复策略由客户端处理。
- 服务端模型代理只处理单次模型请求，工具 API 只执行单次工具任务。服务端不组装对话循环、不自行回填工具结果或继续调用模型。

## 模型

模型与服务商配置有两种来源，按模式区分：

### 云端模式

配置留在服务端，保持一致集中的配置项：

```text
baseURL
API key
protocol
model ID
provider configuration
```

支持协议：

```text
OpenAI Chat Completions
OpenAI Responses
Anthropic Messages
```

**永远不要把服务端模型的 API key 暴露给客户端。** 客户端获取安全的服务商/模型元数据和输入能力，由本地 Runtime 发起单次模型代理请求。代理转发模型的流式响应，包括工具调用事件；后续工具调度与模型轮次由客户端推进。

### 本地模式

用户先配置服务商（名称、协议、base URL、key），再把多个模型挂到对应服务商下。支持从服务商的 `/v1/models` 目录获取模型，也允许手动添加模型 ID。

- Web key 单独保存在浏览器 IndexedDB 的 `model-credentials` 记录中，刷新后仍可用；该记录不加密，界面上必须说明。它**不写入 `model-preferences` 或工作区记录、不写入日志、不写入崩溃上报、不同步到云端**。
- 允许自定义 base URL，以覆盖兼容层服务商。
- 服务商和模型元数据按 Provider 结构保存在本地；读取旧版扁平模型配置时按协议和 Base URL 迁移分组。
- 界面要能展示当前用的是哪种模式的模型，避免用户混淆。

### 共同约束

模型的输入能力要分别记录 `text` 和 `image`，不要合并成一个笼统的多模态标志。

## 工具

**云端工具仅在已登录且具备对应能力时开放，实际执行在服务端，调度在客户端本地 Runtime。**

工具是独立模块，每个工具包含：

```text
name
description
input schema
execute()
```

执行前必须校验输入。

```text
<server-tools-module>/
├── web-tools/
├── file-tools/
└── memory/
```

工具在服务端执行前必须校验用户身份、资源归属、输入大小和运行时限制。

客户端工具适配层只负责提交调用和接收结果，不在设备上执行网络搜索、网页抓取或文件解析。本地模式不注册云端工具。

---

## 联网搜索

联网搜索由 API 进程内的 `app/tools/search.py` 完成：并行请求 DuckDuckGo HTML（失败回退 lite 端点）与 Bing RSS，规范化、去重后返回，**仅云端模式可用**。

把它放在专门的工具模块之后，不要把上游地址和解析逻辑散落到代码各处；单一来源失败时降级，全部失败返回 502。

本地模式下联网搜索入口**不显示**，见「功能可见性」。不要做成灰置或点击报错。

## 当前 Web 实现

- 参考 `../openstudio/src/server/agent/models.ts` 的配置字段与三协议映射，使用固定版本 `@mariozechner/pi-agent-core` / `pi-ai` 0.73.1；服务商密钥和配置不从 OpenStudio 导入。当前仅本地文本对话，不提供工具、图片上传或云端代理。
- `core/agent/runner.ts` 创建真实 pi Agent；`core/llm/model-config.ts` 映射模型元数据；`features/chat/chat-runtime.tsx` 连接当前工作区、上下文、生命周期与消息状态。Thinking Effort 支持 Default、Low、Medium、High，由 pi-agent-core 映射到模型请求；每个会话独立保存设置，新会话沿用最近选择，旧会话读取时默认为 Default，重试沿用会话设置。一个工作区同时生成一条回复，切换聊天或进入设置不卸载 Runtime，删除正在生成的会话会取消，不重建已删会话。
- `features/models/model-settings-screen.web.tsx` 管理 Provider 与其模型；模型目录由 `core/llm/provider-catalog.web.ts` 从服务商直接获取。API key 按 Provider ID 单独存储，持久化的模型配置只保存字段白名单。
- 输入校验通过后才提交消息并清空草稿；未配置模型或缺 key 时保留草稿。流式界面约 50ms 合并一次更新；存储约 300ms 写入最新正文，结束时立即提交最终状态。停止和错误保留收到的文本；刷新时将 streaming 状态恢复为 stopped，不自动继续付费请求。
- 上下文包含当前会话已有文本，不混入其他会话或隐藏思考；使用保守字符预算检查并预留输出窗口，超限提示新建对话。单请求上限 120 秒，本地模式不执行模型返回的工具调用。支持重试最后一条失败/中止回复。
- Web 密钥按工作区单独存放，与模型元数据分表，不写日志或同步。Web 请求经本站同源中继转发，不要求服务商允许浏览器跨域；原生端直连。认证、额度、限流、模型不存在、上下文超限、网络和服务端错误会归一为可操作的安全提示，不直接显示或持久化 SDK 原始响应。生成失败时在回复列表末尾显示错误和重试按钮；空失败回复不渲染成空助手气泡，已有的部分回复会保留。失败轮次只是一条错误状态，不进入后续请求上下文：重新生成按原问题重发，发送新消息时会先移除该失败轮次。切到其他对话时，侧栏标记尚未查看的失败对话；打开后清除未读标记。
- 旧 pi 的聚合入口含 Metro 不支持的动态 Node 导入。`metro.config.js` 在 Web 中把 pi-ai 聚合入口映射为 `pi-agent-bridge.ts` 的官方事件/校验工具导出，并把 Node 环境密钥发现映射为 `pi-browser-credentials.ts`；请求由显式 streamFn 只加载三种协议，未改写依赖文件。升级 pi 时需同时检查这些固定版本的内部工具路径。

- Runtime 的 `ReplyUpdate.reasoningActive` 跟随 pi 的 `thinking_start/delta/end` 更新，正文 `text_start/delta` 和消息结束也会结束思考状态。UI 不再用整轮 streaming 状态决定思考动画；临时标记不持久化，历史消息按结束状态显示。
