# 产品与开发顺序

[文档索引](README.md)

## 项目

> 本文是产品目标与开发路线。本地模式、Web 界面和 Python 后端已完成；账号登录、测试功能开关与云端仓储（在线读写）已接入，本地与账号数据独立。进度见[迁移记录](migration.md)。

Matrius 是一个轻量、多用户、可自行部署的 AI 对话应用。

用户在一个界面里使用不同模型，结合联网搜索、文件阅读和个人记忆完成对话。客户端当前只提供 Web 版本，移动 Web 响应式适配后续再做。

**应用有两种运行模式：不登录即可使用的本地模式，和登录后获得完整能力的云端模式。** 两者共用同一套界面，数据模型一致，区别在于数据存哪、有哪些能力；模型配置与 key 始终来自本机。详见「运行模式」。

核心栈：

* **客户端：** Expo Web（React Native Web）/ TypeScript
* **客户端存储：** 浏览器 IndexedDB
* **后端：** Python 3.12 + FastAPI + SQLAlchemy 2 / Alembic
* **数据库：** SQLite（WAL 模式，单服务器单实例）
* **Agent Runtime：** 客户端本地运行，负责上下文、循环、工具调度与取消
* **限流与短期缓存：** API 进程内存（单 worker）
* **联网搜索 / 网页提取：** DuckDuckGo + Bing、trafilatura
* **文件存储：** 服务器本地文件系统（`DATA_DIR/files`）
* **文档处理：** pypdf、python-docx、openpyxl、python-pptx；其他文件按纯文本读取

产品定位是通用的 AI 对话应用，不是编码 Agent 产品。

## 运行模式

两种模式必须共用同一套数据模型和界面，**不要为本地模式再写一套页面**。

### 本地模式（未登录）

```text
自带 API key
纯对话 + 个人记忆
数据只存在本机
无工具能力
```

- 用户自己配置模型服务商、API key 和模型 ID，客户端**直连**服务商接口。
- **不提供任何工具能力**：没有联网搜索、没有文档读取、没有 MCP。这是明确的产品边界，文件解析和外部工具执行统一留在服务端。
- **没有资料库**：资料库依赖云端文件存储，本地模式下整个功能不显示，也不提供任何上传到云端的入口。
- 记忆助手可用，用它自己的 key 跑提炼流水线。
- 数据保存在客户端本地库：当前浏览器，不做服务端上传。
- 首次打开应用不应强制登录或强制创建管理员。本地模式是合法的使用路径。

### 云端模式（已登录）

```text
客户端 BYOK，同源中继转发模型请求
完整能力：工具、联网搜索、文件读取
数据以服务端为唯一事实源，不做本地缓存，必须联网
```

- Agent Runtime 仍在客户端本地运行，由客户端推进每轮模型调用与工具调度。
- 模型 API key 仍由客户端安全存储保管，经同源 `/api/model-proxy` 转发；服务端不持久化 key。服务端单次模型代理是后续阶段，本期不实现。
- 由本地 Runtime 调用云端工具 API，网络搜索、网页读取和文件处理在服务端执行。
- 网络工具默认开启，可在「设置 → 账号」关闭；关闭后不再注册工具，适合只需要模型和已有资料的场景。
- 会话、消息、已读状态、记忆、画像、偏好和文件元数据保存在服务端，按 `userId` 隔离。
- 新会话不写入本地持久化；断网时不能读取历史，界面提示需要联网。

### 模式切换

- 未登录 → 登录：直接加载当前账号的云端数据，不上传或合并本地工作区；模型配置与 key 继续共用本机配置。
- 已登录 → 登出：回到本地模式，使用登出前已有的本地数据；云端模式期间新产生的数据只在服务端。
- 云端模式下只有一条写入路径：服务端。不存在本地副本需要合并。

### 能力对照

| 能力             | 本地模式 | 云端模式 |
| ---------------- | -------- | -------- |
| 多模型对话       | ✅       | ✅       |
| 流式回复         | ✅       | ✅       |
| 个人记忆         | ✅       | ✅       |
| 记忆助手         | ✅       | ✅       |
| 资料库           | 不显示   | ✅       |
| 文件上传         | 不显示   | ✅       |
| 文件读取         | 不显示   | ✅       |
| 联网搜索         | 不显示   | ✅（可在账号设置关闭） |
| 多用户 / 管理    | 不显示   | ✅       |
| 跨设备访问       | 不显示   | ✅       |

### 功能可见性

上表中标为「不显示」的能力，入口**整体隐藏**，不要做成灰置按钮或点击报错——点了才知道没有的功能比没有这个功能更糟。

- 由**统一的当前能力集**驱动界面的显示与隐藏，不要在页面里散落 `if (isLoggedIn)` 判断。
- 提供一个**统一的登录引导入口**（设置页或侧栏底部），一处说明登录后能获得哪些能力。**不要**在每个缺失的功能位都塞一个"请登录"，那会把界面变成广告位。
- 登录状态变化时能力集立即重算，界面即时响应，不要要求用户重启应用。
- 隐藏只处理可见性，**不代替权限校验**。云端接口仍然要独立校验身份和归属。

## 开发顺序

本地模式、Python 后端和云端仓储已接入。登录前后工作区独立，服务端是云端唯一事实源，当前不做离线队列。

已完成：

```text
1. Expo Web 应用外壳、Expo Router 路由与主题
2. Web 本地存储（IndexedDB）、版本迁移与仓储边界
3. 客户端模型直连：SSE 分帧 + 三协议解码器 + 统一事件模型
4. 本地模式：BYOK 配置与安全存储
5. 客户端本地 Agent Runtime：对话循环、状态、取消与消息持久化
6. 后端：认证、管理员、会话/消息、账号数据、文件、搜索与网页读取
7. 后端：进程内限流/缓存、SQLite 与本地文件存储、Caddy / Web / API 三容器 Compose、远程发布与健康检查
```

下一步：

```text
8. 客户端 API 层：登录/改密、Bearer 会话、功能开关及账号导入已完成；云端 CRUD 的错误与 409 冲突提示已接入
9. 工作区隔离：登录使用账号云端 REST，退出恢复本地；不再自动导入或双向合并，模型配置与 key 在本机共用
10. 云端模式：会话列表/详情在线读写，消息在回复结束后 POST
11. 云端模式：打开会话时同步已读状态；页面聚焦时刷新
12. 云端模式：把 Runtime 工具调用接到搜索、网页读取、文件 API
13. 云端模式：文件上传与 fileId 引用
14. 服务端单次模型代理（取代客户端 key，另立阶段）
15. MCP / 额外工具
```

不要提前构建：

```text
多 Agent 编排
工作流引擎
插件市场
复杂角色系统
组织 / 租户系统
```

## 账号功能逐步开放

同一地址、同一套前后端，按已认证账号开放功能。新功能默认 preview，仅 `admin_test` 可以看见和调用；通过验证后逐项标为 stable，下次部署时对已登录账号生效。权限集中在功能清单，前端隐藏入口、后端独立校验，不引入角色权限系统。登录后的数据同步已接入；云端仓储（服务端唯一事实源）仍待实现。规则见[认证文档](auth.md#同一地址的账号功能开关)。
