# 产品与开发顺序

[文档索引](README.md)

## 项目

> 本文是从旧工程迁移的产品目标与开发路线，不代表当前 Expo 客户端已实现。当前先做 Web 界面，移动端后续适配，进度见[迁移记录](migration.md)。

Matrius 是一个轻量、多用户、可自行部署的 AI 对话应用。

用户在一个界面里使用不同模型，结合联网搜索、文件阅读和个人记忆完成对话。客户端同时支持 Web、Android 和 iOS。

**应用有两种运行模式：不登录即可使用的本地模式，和登录后获得完整能力的云端模式。** 两者共用同一套界面，数据模型一致，区别在于数据存哪、模型 key 从哪来、有哪些能力。详见「运行模式」。

核心栈：

* **客户端：** React Native + Expo / TypeScript（Android、iOS、Web）
* **客户端存储：** Web 使用浏览器 IndexedDB；App 后续使用手机本地数据库，优先评估 Expo SQLite
* **后端：** 待定（语言、框架与运行时尚未确定）
* **数据库：** PostgreSQL
* **Agent Runtime：** 客户端本地运行，负责上下文、循环、工具调度与取消
* **云端缓存 / 工具任务状态：** Redis
* **联网搜索：** OpenSERP
* **文件存储：** RustFS（S3 兼容）
* **文档处理：** 后端侧实现，选型随后端技术栈确定

产品定位是通用的 AI 对话应用，不是编码 Agent 产品。

## 运行模式

两种模式必须共用同一套数据模型和界面，**不要为本地模式再写一套页面**。

### 本地模式（未登录）

```text
自带 API key
纯对话 + 个人记忆
数据只存在本机
无工具能力
```

- 用户自己配置模型服务商、API key 和模型 ID，客户端**直连**服务商接口。
- **不提供任何工具能力**：没有联网搜索、没有文档读取、没有 MCP。这是明确的产品边界，文件解析和外部工具执行统一留在服务端。
- **没有资料库**：资料库依赖云端文件存储，本地模式下整个功能不显示，也不提供任何上传到云端的入口。
- 记忆助手可用，用它自己的 key 跑提炼流水线。
- 数据保存在客户端本地库：Web 在当前浏览器，App 在手机上，不做服务端上传。
- 首次打开应用不应强制登录或强制创建管理员。本地模式是合法的使用路径。

### 云端模式（已登录）

```text
服务端保管 API key
完整能力：工具、联网搜索、文件读取
数据以服务端为事实源，本地保留离线缓存
```

- Agent Runtime 仍在客户端本地运行，由客户端推进每轮模型调用与工具调度。
- 模型请求通过服务端单次代理转发，客户端**不接触**服务端配置的 API key。
- 由本地 Runtime 调用云端工具 API，网络搜索、网页读取和文件处理在服务端执行。
- 数据同步到服务端，按 `userId` 隔离。
- 本地库继续保留，作为离线缓存和后续增量同步的基础。

### 模式切换

- 未登录 → 登录：把本地数据**上传合并**到云端，本地副本**保留**作为离线缓存。合并过程要可中断、可重试，失败不得丢数据。
- 已登录 → 登出：本地缓存**保留**，不要清除。用户重新登录后应能继续离线查看。
- 切到云端模式后，**云端是事实源**，本地是副本。不要在两边都能写的情况下放任各自演化——写入路径必须明确。

### 能力对照

| 能力             | 本地模式 | 云端模式 |
| ---------------- | -------- | -------- |
| 多模型对话       | ✅       | ✅       |
| 流式回复         | ✅       | ✅       |
| 个人记忆         | ✅       | ✅       |
| 记忆助手         | ✅       | ✅       |
| 资料库           | 不显示   | ✅       |
| 文件上传         | 不显示   | ✅       |
| 文件读取         | 不显示   | ✅       |
| 联网搜索         | 不显示   | ✅       |
| 多用户 / 管理    | 不显示   | ✅       |
| 跨设备同步       | 不显示   | ✅       |

### 功能可见性

上表中标为「不显示」的能力，入口**整体隐藏**，不要做成灰置按钮或点击报错——点了才知道没有的功能比没有这个功能更糟。

- 由**统一的当前能力集**驱动界面的显示与隐藏，不要在页面里散落 `if (isLoggedIn)` 判断。
- 提供一个**统一的登录引导入口**（设置页或侧栏底部），一处说明登录后能获得哪些能力。**不要**在每个缺失的功能位都塞一个"请登录"，那会把界面变成广告位。
- 登录状态变化时能力集立即重算，界面即时响应，不要要求用户重启应用。
- 隐藏只处理可见性，**不代替权限校验**。云端接口仍然要独立校验身份和归属。

## 开发顺序

先做本地模式，让它能独立跑起来——它不依赖尚未定型的后端。

```text
1. React Native + Expo 应用外壳、Expo Router 路由与主题
2. 客户端本地存储骨架（存储选型、schema 版本管理、移动端与 Web 持久化验证）
3. 客户端直连模型：SSE 分帧 + 三协议解码器 + 统一事件模型
4. 本地模式：BYOK 配置与安全存储
5. 客户端本地 Agent Runtime：对话循环、状态、取消与消息持久化（未登录不注册云端工具）
6. 本地模式：记忆基础能力（增删改查与查看界面）
7. 本地模式：记忆助手后台提炼流水线
8. 本地模式：上下文注入
9. 后端骨架与健康检查
10. 服务端初始化与登录 / 登出 / 首次登录改密
11. 管理员用户管理
12. 本地 Agent Runtime 接入云端单次模型代理与工具 API
13. 云端模式：本地 Runtime 的工具循环、流式事件与对话持久化
14. 数据同步：本地数据上传合并（单向）
15. 云端模式：OpenSERP 联网搜索
16. 云端模式：RustFS 文件上传与文件读取工具
17. 云端模式：记忆助手服务端代理与记忆工具
18. Redis 云端缓存、限流与工具任务协调
19. 数据同步：双向增量同步与冲突解决
20. MCP / 额外工具
```

不要提前构建：

```text
多 Agent 编排
工作流引擎
插件市场
复杂角色系统
组织 / 租户系统
```
