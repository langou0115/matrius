# 存储与数据同步

[文档索引](README.md)

## 客户端本地存储

- 旧工程的 drift 是 Dart 库，新客户端不再沿用；保留本地优先、迁移和仓储边界。
- “本地”按运行平台定义：Web 保存在当前浏览器，App 保存在手机应用本地目录，与是否登录是两回事。
- Web 已接入浏览器 IndexedDB：数据库 `matrius`、版本 2。`state.workspace` 保存版本化的会话元数据、消息键列表、当前会话、侧栏状态和外观偏好；`messages` store 独立保存消息正文、回复状态、实际返回的推理与安全错误提示。Thinking Effort 按会话和最近选择保存在工作区元数据；读取旧会话时补为 Default。未发送草稿仍仅保存在页面内存。
- 分支对话复用现有会话结构：创建新会话 ID 与新消息 ID，复制源会话开头至选中 AI 回复（含本条）的原文及反馈；原会话不改写。正常模式沿现有保存队列写入 IndexedDB，Mock 模式仅在内存中更新，不新增数据库结构。
- 助手消息的可选 `feedback` 保存为 `good` 或 `bad`，赞踩互斥，再次点击取消并删除该字段。反馈与消息一起持久化，刷新和切换页面后保留；旧记录不补默认评分，加载时忽略用户消息和非法值上的反馈。下一次模型请求由共享 Agent 上下文组装反馈，不单独调用外部评分接口。
- 用户消息可带可选的 `quote` 原文，与消息正文一起写入现有 `messages` store，刷新、重新生成及创建分支均保留；旧记录缺少该字段时不添加引用，不改变数据库版本。未发送引用与文字草稿按会话保存在 Draft Context 内存中；导航卡片的展开与当前阅读位置不持久化。
- 会话元数据可带 `titleSource`：`auto` 表示标题仍是首条消息的临时截断、等待 AI 生成；`ai` 表示已使用生成的标题；`manual` 表示用户重命名或分支创建，永不被迟到的生成结果覆盖。字段随工作区快照保存，旧记录缺失时视为不使用自动标题；非法值在加载时丢弃。AI 标题生成本身不写入消息正文或未读状态。
- 会话元数据可带 `completedReadAt`：值为 `null` 表示回复在后台完成且尚未查看，数字表示已读时间；旧记录缺少该字段表示没有未读完成。它随工作区快照持久化，刷新后侧栏仍显示完成标记；打开会话、发送新消息或开始新一轮生成时清除。`chatVisible`（聊天屏是否挂载）只存在于当前标签页内存，不写入工作区，用于区分“设置页待完成”和“用户正在看该会话”。
- 个性化偏好作为工作区元数据的可选 `personalization` 字段保存，包含 `customInstructions`、`aboutName`、`occupation`、`aboutMore`；与对话共用现有事务和 revision 冲突保护，不新增 store 或更改数据库版本。旧快照缺失字段时补为空值；字段长度分别限制为 10000、100、100、4000 字符，写入和加载时均校验。设置更改自动保存，Mock 仅更新内存。个性化不含自动记忆数据，不写入消息正文；模型请求会包含用户填写的资料。
- 浏览器数据库按站点来源隔离，不同域名或端口的数据不共享。清除网站数据会删除记录，隐私窗口数据保留范围由浏览器控制。
- 首次渲染先完成数据库读取与结构校验，再挂载业务 Provider，避免空初始状态覆盖已有数据。读取失败明确提示并允许重试，不覆盖旧数据。
- 保存按操作顺序排队，以数据库事务完成作为成功。读取和写入均检查版本；其他标签页改写后，本页后续保存会提示冲突，不静默覆盖。当前不提供多标签页自动合并。
- v2 升级迁移在 `core/database/browser-store.web.ts` 的 `onupgradeneeded` 中创建 `messages` store；旧版快照保留可读，在下一次保存事务中原子转换。流式正文按独立消息增量写入，元数据和消息共享 workspace revision 校验。仍未实现实体同步与墓碑，不能将本地元数据记录当作同步协议。
- App 的手机本地数据库尚未接入，后续优先评估 [Expo SQLite（SDK 57）](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/)。平台适配与 Web 实现分离，页面不直接访问数据库。
- 模型 API key 与认证令牌通过安全存储适配层管理，不存入普通业务表或同步载荷。Web 把它们单独写入 `state.model-credentials` 记录（未加密，与 `model-preferences` 分离）；App 后续交给手机本地数据库。浏览器端限制见[客户端约定](client.md)。
- 不自动导入旧工程设备数据库或历史用户数据；后续如需导入，单独定义导出格式、版本映射与回滚流程。

## 数据同步

同步是本项目**最复杂的模块**，按「先单向、后双向」推进，不要在早期就承诺双向同步。

### 同步范围

```text
对话
消息
记忆条目
用户画像字段
设置与偏好
```

文件不在此列——文件内容始终在 RustFS，同步的只是元数据。

### 本地库始终保留

本地库不是临时缓存，任何时候都可以从它读取。云端模式下：

- **服务端是事实源**，本地是副本。
- 写入先落本地、再推送云端（离线优先），失败进重试队列，不要因为网络失败就丢掉用户的输入。
- 网络不可用时应用必须仍然可读、可写。

### 同步元数据

凡是要同步的表都要带同步字段。这些字段是同步机制的必需成本，不要试图省掉：

```text
remoteId        # 服务端 id，未同步时为 null
revision        # 服务端版本号，用于冲突检测
syncedAt        # 上次成功同步时间
deletedAt       # 墓碑，软删除时间
```

- **删除必须写墓碑，不能物理删除**，否则删除操作无法传播，同步回来会"复活"。
- 墓碑要能被清理（保留期后物理删除），否则表会无限增长。

### 冲突解决

- 默认采用**最后写入获胜**，以服务端时间为准。规则要单一、可预测，不要在不同表上用不同策略。
- 服务端用 `revision` 做乐观并发控制，客户端提交时带上已知 `revision`，不匹配则拒绝并返回服务端版本。
- 记忆条目的冲突可以温和处理（都保留、标记疑似重复），不要静默丢弃用户的记忆。
- 冲突被检测到时**不要静默解决**，至少要让用户能感知到哪条数据被覆盖了。

### 首次合并

未登录转登录时，把本地数据上传合并：

- 分批上传，支持中断续传，**失败不得丢数据**。
- 本地已有的 id 与服务端 id 不同域，用 `remoteId` 建立映射，不要用本地 id 直接当服务端主键。
- 合并完成后回写 `remoteId` 和 `revision`，把本地记录标记为已同步。
- 合并过程中显示进度，不要给用户一个没有任何反馈的长时间等待。

### 增量拉取

- 服务端要支持**按时间或版本号拉取增量**，不要让客户端每次全量拉取。
- 客户端记录上次同步水位，断点续传。

## PostgreSQL

PostgreSQL 是云端模式持久数据的唯一事实来源，保存：

```text
users
conversations
messages
settings
file metadata
memory_entries
user_profile_fields
```

结构变更使用迁移（migration）。

不要把上传文件的二进制内容存进 PostgreSQL。

### 服务端表结构注意事项

- 所有同步实体都要有 `revision`（版本号）和 `deleted_at`（墓碑）。
- 记忆表要按 `userId` 建索引，并按更新时间支持增量拉取。
- 不要用客户端的本地 id 作主键。客户端上传时由服务端分配 id，返回给客户端写入 `remoteId`。

---

## Redis

Redis 只用于临时和运行时数据：

```text
缓存
限流
云端工具任务状态
单次请求协调
锁
同步任务协调
```

不要把 Redis 当作主要的持久化数据库。Agent Runtime 的循环状态与可恢复进度由客户端本地管理，不存放在 Redis 中推进。

---

## RustFS

RustFS 保存上传文件的实际内容，**仅云端模式可用**。

```text
PostgreSQL
└── 文件元数据
    ├── id
    ├── userId
    ├── filename
    ├── objectKey
    ├── contentType
    └── size

RustFS
└── 文件二进制内容
```

读取或删除文件前必须验证归属。`objectKey` 可以带用户目录前缀，但目录前缀不能替代数据库归属校验。

## 本地模型与流式消息

- `state.model-preferences` 独立保存经过白名单校验的 Provider 配置、其模型元数据、当前模型选择与可选 `titleModelId`，带独立 revision；`titleModelId` 为 `null` 时标题跟随会话模型，指向已删除或未知模型时加载归一为 `null`。API key 不在这个记录或工作区记录中，按 Provider ID 存在旁边的 `state.model-credentials`，两份记录各有 revision，写入冲突按现有约定提示而不合并。读取旧版扁平模型项时按协议、Base URL 和鉴权要求迁移为 Provider 分组。Mock 使用独立内存配置，不读取正式模型配置与 key。
- 工作区元数据、变化的消息正文与已删除消息的清理在同一事务内提交。停止或错误时保留部分正文；恢复 streaming 消息时标记为 stopped，不自动继续请求。流式保存合并到约 300ms 一次，退出页面前尚未完成的写入不承诺保存。
- 助手消息另外记录 `thinkingMs`（发送到最后一个思考 token 的毫秒数），用于刷新后仍能在思考区显示耗时。没有思考内容的消息不带这个字段；它随消息正文一起存储，读取时按白名单校验，非法值直接丢弃而不是让整条工作区加载失败。
- 现阶段仅本地存储，删除消息会移除本地正文；同步实现前仍需加入墓碑和服务器实体版本。
