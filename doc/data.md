# 存储与数据同步

[文档索引](README.md)

## 客户端本地存储

- 旧工程的 drift 是 Dart 库，新客户端不再沿用；保留本地优先、迁移和仓储边界。
- “本地”按运行平台定义：Web 保存在当前浏览器，App 保存在手机应用本地目录，与是否登录是两回事。
- Web 已接入浏览器 IndexedDB：数据库 `matrius`、版本 1、`state` store 内的 `workspace` 记录保存当前对话列表、消息、置顶状态、当前会话、侧栏状态和外观偏好。未发送草稿仍仅保存在页面内存。
- 分支对话复用现有会话结构：创建新会话 ID 与新消息 ID，复制源会话开头至选中 AI 回复（含本条）的原文；原会话不改写。正常模式沿现有保存队列写入 IndexedDB，Mock 模式仅在内存中更新，不新增数据库结构。赞/踩选中状态仅保存在消息操作组件内，不进入持久数据。
- 浏览器数据库按站点来源隔离，不同域名或端口的数据不共享。清除网站数据会删除记录，隐私窗口数据保留范围由浏览器控制。
- 首次渲染先完成数据库读取与结构校验，再挂载业务 Provider，避免空初始状态覆盖已有数据。读取失败明确提示并允许重试，不覆盖旧数据。
- 保存按操作顺序排队，以数据库事务完成作为成功。读取和写入均检查版本；其他标签页改写后，本页后续保存会提示冲突，不静默覆盖。当前不提供多标签页自动合并。
- 当前为本地 UI 阶段的版本化工作区快照。接入流式消息、记忆和同步前，应迁移到按实体访问的仓储、增量写入和墓碑；不能把全量快照当作同步协议。
- App 的手机本地数据库尚未接入，后续优先评估 [Expo SQLite（SDK 57）](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/)。平台适配与 Web 实现分离，页面不直接访问数据库。
- 模型 API key 与认证令牌通过安全存储适配层管理，不存入普通业务表或同步载荷。浏览器端限制见[客户端约定](client.md)。
- 不自动导入旧工程设备数据库或历史用户数据；后续如需导入，单独定义导出格式、版本映射与回滚流程。

## 数据同步

同步是本项目**最复杂的模块**，按「先单向、后双向」推进，不要在早期就承诺双向同步。

### 同步范围

```text
对话
消息
记忆条目
用户画像字段
设置与偏好
```

文件不在此列——文件内容始终在 RustFS，同步的只是元数据。

### 本地库始终保留

本地库不是临时缓存，任何时候都可以从它读取。云端模式下：

- **服务端是事实源**，本地是副本。
- 写入先落本地、再推送云端（离线优先），失败进重试队列，不要因为网络失败就丢掉用户的输入。
- 网络不可用时应用必须仍然可读、可写。

### 同步元数据

凡是要同步的表都要带同步字段。这些字段是同步机制的必需成本，不要试图省掉：

```text
remoteId        # 服务端 id，未同步时为 null
revision        # 服务端版本号，用于冲突检测
syncedAt        # 上次成功同步时间
deletedAt       # 墓碑，软删除时间
```

- **删除必须写墓碑，不能物理删除**，否则删除操作无法传播，同步回来会"复活"。
- 墓碑要能被清理（保留期后物理删除），否则表会无限增长。

### 冲突解决

- 默认采用**最后写入获胜**，以服务端时间为准。规则要单一、可预测，不要在不同表上用不同策略。
- 服务端用 `revision` 做乐观并发控制，客户端提交时带上已知 `revision`，不匹配则拒绝并返回服务端版本。
- 记忆条目的冲突可以温和处理（都保留、标记疑似重复），不要静默丢弃用户的记忆。
- 冲突被检测到时**不要静默解决**，至少要让用户能感知到哪条数据被覆盖了。

### 首次合并

未登录转登录时，把本地数据上传合并：

- 分批上传，支持中断续传，**失败不得丢数据**。
- 本地已有的 id 与服务端 id 不同域，用 `remoteId` 建立映射，不要用本地 id 直接当服务端主键。
- 合并完成后回写 `remoteId` 和 `revision`，把本地记录标记为已同步。
- 合并过程中显示进度，不要给用户一个没有任何反馈的长时间等待。

### 增量拉取

- 服务端要支持**按时间或版本号拉取增量**，不要让客户端每次全量拉取。
- 客户端记录上次同步水位，断点续传。

## PostgreSQL

PostgreSQL 是云端模式持久数据的唯一事实来源，保存：

```text
users
conversations
messages
settings
file metadata
memory_entries
user_profile_fields
```

结构变更使用迁移（migration）。

不要把上传文件的二进制内容存进 PostgreSQL。

### 服务端表结构注意事项

- 所有同步实体都要有 `revision`（版本号）和 `deleted_at`（墓碑）。
- 记忆表要按 `userId` 建索引，并按更新时间支持增量拉取。
- 不要用客户端的本地 id 作主键。客户端上传时由服务端分配 id，返回给客户端写入 `remoteId`。

## Redis

Redis 只用于临时和运行时数据：

```text
缓存
限流
云端工具任务状态
单次请求协调
锁
同步任务协调
```

不要把 Redis 当作主要的持久化数据库。Agent Runtime 的循环状态与可恢复进度由客户端本地管理，不存放在 Redis 中推进。

## RustFS

RustFS 保存上传文件的实际内容，**仅云端模式可用**。

```text
PostgreSQL
└── 文件元数据
    ├── id
    ├── userId
    ├── filename
    ├── objectKey
    ├── contentType
    └── size

RustFS
└── 文件二进制内容
```

读取或删除文件前必须验证归属。`objectKey` 可以带用户目录前缀，但目录前缀不能替代数据库归属校验。
