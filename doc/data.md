# 存储与数据

[文档索引](README.md)

## 唯一事实源

会话、消息、已读、记忆、画像、外观、网络工具偏好、文件元数据和 Token 用量统一保存到实例后端。
浏览器不维护聊天工作区副本，不提供匿名模式、离线写入或本地/云端同步。
UI → features → repository → API → SQLite / 文件系统。

客户端仍使用 IndexedDB 保存模型服务配置和独立的模型密钥记录；当前会话位置等设备状态可留在浏览器。
旧浏览器工作区数据保留但不再加载或写入；`browser-store.ts` 中的历史格式读取与迁移辅助函数不构成产品模式。
`/mock/*` 的工作区和模型配置只在内存中，正式构建不可访问。

## 目录

```text
开发：server/.data/               Docker：/data/
├── matrius.db                   # SQLite；运行时另有 -wal、-shm
├── files/
│   └── <fileId>/
│       └── <文件名>             # 上传和工具保存的文件
└── drafts/
    └── <draftId>/               # 临时文档草稿
```

`DATA_DIR` 是数据根目录，开发固定为 `server/.data`；Docker 挂载到 `/data`。
对象键为 `<fileId>/<safeName>`，不包含用户目录；文件名沿用上传/重命名的安全文件名校验。
上传、文档新建/编辑保存、重命名都使用同一规则。
文件重命名会更新磁盘路径和数据库对象键，数据库提交失败时清理新副本。
同一文件的编辑保存和重命名在单 API worker 内串行执行；覆盖提交失败时恢复原文件内容。
文件内容以临时文件 + `os.replace` 原子替换，路径解析拒绝越出根目录的对象键。
SQLite 事务与文件替换不是跨存储的原子事务；备份和恢复应覆盖数据库与整个文件目录。

## 旧数据迁移

开发启动和 `npm run db:migrate` 在新库不存在时，通过 SQLite backup API 将旧 `server/.data/dev.db`（包括 WAL 中的数据）复制为 `matrius.db`；旧库保留，不覆盖已有新库。
`--reset-db` 明确清空新旧开发数据库、上传文件和草稿，避免旧库被再次导入。

Alembic `0011_remove_accounts` 删除 users、auth_sessions 和所有者绑定，将业务数据统一归属 instance.id=1；画像与偏好表也去除用户命名。迁移先创建完整数据库备份，再优先采用原绑定所有者的重复设置、合计同日用量并去重标记。所有对话、消息、文件和记忆保留；重复旧导入键清空，资源 UUID 与关联不变。被取代的旧设置和原始导入键可从备份恢复，详见[实例访问](instance.md)。

bootstrap 把旧对象键 `users/<userId>/<fileId>/...` 复制为 `<fileId>/<safeName>`，然后提交数据库指针。
复制和提交按文件逐个进行，失败会阻止启动并可重试。旧文件副本保留，避免中断或旧备份失去文件；不自动删除历史实例或其文件。

## 写入与冲突

会话与消息、记忆、画像和偏好使用 `baseRevision` 乐观并发，冲突返回 409；单用户的多设备/多标签页仍需冲突保护。
工作区持久化队列直接调用 REST，流式期间合并保存，完成时提交最终内容；网络失败明确提示，不回退到 IndexedDB。
消息的文件引用、引用原文、反馈、思考与工具顺序、滚动摘要等继续随现有消息结构保存。
图片请求字节不写入聊天工作区快照。
已读与当前设备打开的会话分开；当前会话地址由 Router 与设备状态恢复。

## 临时状态与密钥

搜索结果/文件文本缓存、滑动窗口限流和并发计数存在 API 内存，重启清零。
文档草稿元数据在内存、字节在 drafts 下，重启失效，因此 API 保持单 worker。
Agent 循环、取消、草稿输入和未完成请求运行在浏览器，关闭页面会中断。
模型 API key 只持久化在浏览器，不写日志；模型中继会在单次请求期间转发给服务商，不保存密钥。
