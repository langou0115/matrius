# 存储与数据同步

[文档索引](README.md)

## 客户端本地存储

助手消息的本地 `process` 字段保存按运行事件排序的思考与工具步骤，保留「思考 → 搜索 → fetch → 再思考」顺序；重新加载时将仍在运行的步骤恢复为 stopped。旧消息没有该字段时继续使用原有 reasoning/activities 展示，不推断历史顺序。`thinkingMs` 对新回复记录整轮耗时（包含工具和回答生成）；旧记录保留原值。process 与 activities 仅在本地模式持久化；云端模式只保留当前页面的运行步骤，不上传这些字段，不改变服务端数据库结构。

- 旧工程的 drift 是 Dart 库，新客户端不再沿用；保留本地优先、迁移和仓储边界。
- “本地”按运行平台定义：Web 保存在当前浏览器，App 保存在手机应用本地目录，与是否登录是两回事。
- Web 已接入浏览器 IndexedDB：数据库 `matrius`、版本 2。`state.workspace` 保存版本化的会话元数据、消息键列表、当前会话、侧栏状态和外观偏好；`messages` store 独立保存消息正文、回复状态、实际返回的推理与安全错误提示。Thinking Effort 按会话和最近选择保存在工作区元数据；读取旧会话时补为 Default。未发送草稿仍仅保存在页面内存。
- 分支对话复用现有会话结构：创建新会话 ID 与新消息 ID，复制源会话开头至选中 AI 回复（含本条）的原文及反馈；原会话不改写。正常模式沿现有保存队列写入 IndexedDB，Mock 模式仅在内存中更新，不新增数据库结构。
- 助手消息的可选 `feedback` 保存为 `good` 或 `bad`，赞踩互斥，再次点击取消并删除该字段。反馈与消息一起持久化，刷新和切换页面后保留；旧记录不补默认评分，加载时忽略用户消息和非法值上的反馈。下一次模型请求由共享 Agent 上下文组装反馈，不单独调用外部评分接口。
- 用户消息可带可选的 `quote` 原文，与消息正文一起写入现有 `messages` store，刷新、重新生成及创建分支均保留；旧记录缺少该字段时不添加引用，不改变数据库版本。未发送引用与文字草稿按会话保存在 Draft Context 内存中；导航卡片的展开与当前阅读位置不持久化。
- 会话元数据可带 `titleSource`：`auto` 表示标题仍是首条消息的临时截断、等待 AI 生成；`ai` 表示已使用生成的标题；`manual` 表示用户重命名或分支创建，永不被迟到的生成结果覆盖。字段随工作区快照保存，旧记录缺失时视为不使用自动标题；非法值在加载时丢弃。AI 标题生成本身不写入消息正文或未读状态。
- 会话元数据可带 `completedReadAt`：值为 `null` 表示回复在后台完成且尚未查看，数字表示已读时间；旧记录缺少该字段表示没有未读完成。它随工作区快照持久化，刷新后侧栏仍显示完成标记；打开会话、发送新消息或开始新一轮生成时清除。`chatVisible`（聊天屏是否挂载）只存在于当前标签页内存，不写入工作区，用于区分“设置页待完成”和“用户正在看该会话”。
- 个性化偏好作为工作区元数据的可选 `personalization` 字段保存，包含 `customInstructions`、`aboutName`、`occupation`、`aboutMore`；与对话共用现有事务和 revision 冲突保护，不新增 store 或更改数据库版本。旧快照缺失字段时补为空值；字段长度分别限制为 10000、100、100、4000 字符，写入和加载时均校验。设置更改自动保存，Mock 仅更新内存。个性化不含自动记忆数据，不写入消息正文；模型请求会包含用户填写的资料。
- 浏览器数据库按站点来源隔离，不同域名或端口的数据不共享。清除网站数据会删除记录，隐私窗口数据保留范围由浏览器控制。
- 首次渲染先完成数据库读取与结构校验，再挂载业务 Provider，避免空初始状态覆盖已有数据。读取失败明确提示并允许重试，不覆盖旧数据。
- 页面重新加载后，保存中的 `streaming` 消息与 `running` 工具活动均恢复为中性停止状态，保留部分正文并说明中断原因，不重新发起模型请求。发送后续问题保留上一轮记录；本地和云端工作区独立，不再用同步响应合并会话。
- 保存按操作顺序排队，以数据库事务完成作为成功。读取和写入均检查版本；其他标签页改写后，本页后续保存会提示冲突，不静默覆盖。当前不提供多标签页自动合并。
- v2 升级迁移在 `core/database/browser-store.web.ts` 的 `onupgradeneeded` 中创建 `messages` store；旧版快照保留可读，在下一次保存事务中原子转换。流式正文按独立消息增量写入，元数据和消息共享 workspace revision 校验。这些记录仅服务本地模式。
- App 的手机本地数据库尚未接入，后续优先评估 [Expo SQLite（SDK 57）](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/)。平台适配与 Web 实现分离，页面不直接访问数据库。
- 旧版账号的同步范围选择保存在 `state.account-sync-preferences`，以 `users[userId]` 区分账号，记录聊天记录、已读和未读、个人设置、界面外观四类的布尔值；与工作区一样走 revision 校验和写队列，冲突时重读后重试一次。旧版最后同步时间保存在 `state.account-sync-state`，同样按账号区分。登录令牌仍按标签页隔离，不同步。
- 模型 API key 与认证令牌通过安全存储适配层管理，不存入普通业务表或同步载荷。Web 把它们单独写入 `state.model-credentials` 记录（未加密，与 `model-preferences` 分离）；App 后续交给手机本地数据库。浏览器端限制见[客户端约定](client.md)。
- 不自动导入旧工程设备数据库或历史用户数据；后续如需导入，单独定义导出格式、版本映射与回滚流程。

## 本地与云端隔离

- 未登录使用 `state.workspace` 与 `messages`，只读写当前浏览器 IndexedDB。
- 登录且完成首次改密后，工作区通过 REST 从当前账号读取会话、消息、外观与个性化设置；服务端是唯一事实源。不读取本地工作区、不自动导入、不双向合并，也不把云端内容写入 IndexedDB。
- 退出恢复登录前的本地工作区；切换账号重新加载该账号的数据，同时清空草稿和运行状态、停止旧 Runtime。晚到的账号请求不能继续写入另一个账号。
- 登录恢复验证期间等待验证结果；后台重复验证保留当前工作区，验证失败显示重试，不自动回退本地工作区。
- 模型服务商、模型列表、当前模型、标题模型与 API key 始终保存在本机，所有账号和未登录状态共用；它们不进入账号数据接口。Mock 仍使用独立内存配置。
- 云端修改按顺序写入 REST，修改和删除携带服务端 `baseRevision`；409 或网络失败提示保留内容并重试/刷新，不写本地离线队列。跨设备数据在重新加载工作区时读取；不做后台合并。
- 流式正文在内存中展示，约 1.5 秒保存一次云端快照，只写变化的消息；持久化状态为 stopped，回复结束后保存 complete/error。重新打开不会恢复一个不存在的运行任务。未完成的网络保存不保证在退出或关闭页面后完成。
- 会话与单条消息删除直接调用服务端 API。云端删除不修改本地记录，本地删除不传播到账号。
- 旧版同步已合并到本地或服务器的数据保留原样，无法可靠判断来源，不自动清理。原导入 API 保留兼容，但正常登录流程不调用它；原同步范围与同步时间记录不再参与工作区读写。

## SQLite

SQLite 是云端模式持久数据的唯一事实来源：生产为 `/data/matrius.db`，开发为 `server/.data/dev.db`。保存：

```text
users, auth_sessions
conversations, messages
memory_entries
user_profiles, user_profile_fields, user_preferences
file metadata
```

生产启用 WAL、`foreign_keys=ON`、`busy_timeout`（默认 30 秒）和 `synchronous=NORMAL`。它只支持单机、单实例、单 uvicorn worker；写事务串行化，业务事务要保持短小，文件 I/O 不放在数据库事务内。

结构变更使用 Alembic 迁移，并应在临时空 SQLite 上验证全部迁移可执行；部署时 API 入口会运行 `alembic upgrade head` 和 `alembic check`。

不要把上传文件的二进制内容存进 SQLite。

### 服务端表结构注意事项

- 所有用户数据都有 `user_id`，读写一律带 `WHERE user_id = :current`；跨用户访问返回 404。
- 会话、消息、记忆、文件都有 `revision`（从 1 开始，每次修改 +1），用于乐观并发。
- `client_id` 只用于存量导入与请求幂等，唯一约束为 `(user_id, client_id)`；主键仍是 UUID。
- 会话删除级联消息，同时保存删除标识；不会保留已删除的正文、标题或推理内容。删除标识与导入共用串行锁和事务，任一到达顺序都以删除为准。
- 消息 `position` 在同一个写事务内取 `max(position)+1`，`(conversation_id, position)` 唯一。
- 只读或追加消息时才改变排序时间；修改标题、置顶或已读状态不改变会话在列表中的位置。

## 进程内缓存

API 进程内存只保存临时和运行时数据：

```text
搜索结果缓存（5 分钟）
文件文本缓存（1 小时）
登录失败计数与锁定
滑动窗口限流
```

这些状态随进程重启清零，因此 API 必须单 worker 运行。不要把它当作持久化数据库；Agent Runtime 的循环状态与可恢复进度仍由客户端本地管理。

## 本地文件存储

上传文件的实际内容写在 `DATA_DIR/files`：生产为 `/data/files`（与 `matrius.db` 同在 `matrius_prod_api_data` 卷），开发为 `server/.data/files`。**仅云端模式可用**。对象键为 `users/{userId}/{fileId}/{safeName}`；单文件默认 20 MiB，每用户配额默认 512 MiB。上传类型白名单、解析与读取限制见[后端架构](backend.md)。

```text
SQLite（matrius.db）
└── 文件元数据
    ├── id
    ├── userId
    ├── filename
    ├── objectKey
    ├── contentType
    └── size

DATA_DIR/files
└── 文件二进制内容
```

写入使用临时文件 + `os.replace` 原子替换，并拒绝越出根目录的键。读取或删除文件前必须验证归属；`objectKey` 的用户目录前缀不能替代数据库归属校验。

## 本地模型与流式消息

- `state.model-preferences` 独立保存经过白名单校验的 Provider 配置、其模型元数据、当前模型选择与可选 `titleModelId`，带独立 revision；`titleModelId` 为 `null` 时标题跟随会话模型，指向已删除或未知模型时加载归一为 `null`。API key 不在这个记录或工作区记录中，按 Provider ID 存在旁边的 `state.model-credentials`，两份记录各有 revision，写入冲突按现有约定提示而不合并。读取旧版扁平模型项时按协议、Base URL 和鉴权要求迁移为 Provider 分组。Mock 使用独立内存配置，不读取正式模型配置与 key。
- 工作区元数据、变化的消息正文与已删除消息的清理在同一事务内提交。停止或错误时保留部分正文；恢复 streaming 消息时标记为 stopped，不自动继续请求。流式保存合并到约 300ms 一次，退出页面前尚未完成的写入不承诺保存。
- 助手消息另外记录 `thinkingMs`（发送到最后一个思考 token 的毫秒数），用于刷新后仍能在思考区显示耗时。没有思考内容的消息不带这个字段；它随消息正文一起存储，读取时按白名单校验，非法值直接丢弃而不是让整条工作区加载失败。
- 本地模式删除消息会移除本地正文。云端模式的删除走服务端 API，不使用本地记录；两种模式不要互相推断。
